# Estudos (app pessoal)

App de uso pessoal para organizar estudos, em módulos. Mantido pelo Claude; o dono não acompanha o código e usa o app no PC e no celular.

## Stack
React + TypeScript + Vite + Tailwind v4 + Dexie (IndexedDB, local-first) + vite-plugin-pwa. Roteamento com HashRouter.
Fontes locais via `@fontsource` e `@fontsource-variable`, para funcionar offline: Barlow (corpo), Big Shoulders Display (títulos e botões) e Space Mono (números) em todo o app; Fraunces e Archivo Narrow na página inicial e na marca "Estudos" da lateral; `src/styles/fonts.ts` importa todas; `src/fonts.d.ts` declara o pacote da Big Shoulders, que não traz tipos; Young Serif e Newsreader itálico no mundo sacro, com Cinzel Decorative no título; Century por dentro da UEM (eva), que vem no Windows mas é paga, com Old Standard TT nos outros aparelhos; o título da UEM é um desenho (`UemLogo` em `components/worlds/headers.tsx`), inspirado em `refs/uem-eva/uem_fonte.jpg`; Bookman Old Style no Repertório (bebop) onde estiver instalada, com Besley nos outros aparelhos (amostra em `refs/repertorio-bebop/repertorio_fonte.jpg`); Newsreader itálico nas frases do bebop; Anton, Krona One (título) e Special Elite (office); VT323 e Silkscreen (fosforo); Nebula Sans (neural, licença OFL). O PWA guarda fontes e imagens no cache (`workbox.globPatterns` em `vite.config.ts`).

## Estrutura de `src/`
- `pages/`: `HomePage`, `ModulePage`, `TopicPage`. As partes de cada uma ficam em `pages/home/` (`ModuleBanner`, `Barcode`, `scroll`, `transitions`) e `pages/module/` (`headers`, `GroupSection`, `overview`, `rows`, `GroupFooter`, `Intro`, `GroupTitle`, `helpers`).
- `components/`: `ui/` (peças gerais e marcadores), `topic/` (checklist e materiais), `worlds/` (o que é de um mundo: cabeçalhos em `headers.tsx`, fundos dos banners em `BannerBackdrop.tsx`, fundo temático, capa, Getsêmani, virada do alien).
- `core/`: banco, módulos, consultas, carga de conteúdo. `data/`: conteúdo, imagens e créditos. `styles/`: `styles/index.css`, `styles/worlds.css` e `fonts.ts`.

## Modelo de dados (`src/core/db.ts`)
Um modelo só para todos os módulos: módulo > grupo (etapa, disciplina, assunto...) > tópico > checklist, materiais, sessões.
- `groups`, `topics`, `checks` (checklist, agrupado por `section`), `resources` (links, vídeos do YouTube e arquivos em Blob), `sessions`, `meta`.
- Vídeo do YouTube é guardado só pelo id (`kind: 'youtube'`); link comum guarda o endereço; arquivo guarda o Blob.
- Dexie v1 era o protótipo (`pessoal_*`); v2 migra para o modelo atual; v3 remove as tabelas antigas.

## Módulos (`src/core/modules.ts`)
profissional, trabalho, ia, uem, igreja, cultura, mental. Os ids `cultura` e `mental` aparecem na tela como Repertório e Motivação (renomeados em 27/10/2026; o id ficou para não perder dados salvos). As telas são as mesmas para todos (`pages/ModulePage.tsx` e `pages/TopicPage.tsx`).
Para criar um módulo: adicione em `modules.ts` (com o `world`), uma cor em `src/styles/index.css` (`[data-module='x']`, tema escuro e claro) e o conteúdo em `src/data/content/`.
Cada módulo tem a sua cor, e `.app` mistura essa cor no fundo e tinge a lateral (`--*-base` são os neutros). O tema padrão é escuro, com alternância para claro.

## Regras para escolher links
- Nunca inventar URL nem id de vídeo. Buscar na web e **verificar**: YouTube pelo oEmbed (confirma que existe e mostra o título/autor reais), o resto por HTTP. Em 26/10/2026, 198 links verificados; só LeetCode e Linux Journey respondem 403 a robôs, mas abrem para pessoas.
- Conferir o idioma real pelo título/autor do oEmbed (já aconteceu de um vídeo "de Angular" ser em espanhol). Português primeiro; inglês só se for didático, marcado com "(EN)".
- Vídeos não foram assistidos pelo Claude. Descrição de curso só quando o site informou; senão, texto neutro.

## Comandos
`npm run dev`, `npm run build`, `npm run lint`. No Linux o Node está em `~/.local/node/bin` e o `npm` funciona no Bash. No Windows o Node foi instalado via winget; lá o `npm` não está no PATH do Bash, use o PowerShell.
Ao gravar arquivos com PowerShell 5.1, não use `Set-Content -Encoding utf8` (grava BOM e quebra o `package.json`); use `[System.IO.File]::WriteAllText` com `UTF8Encoding($false)` ou as ferramentas de edição.
Não suba o servidor na porta 5173 em testes: o dono costuma deixar o dele rodando lá. Use outra porta e encerre depois.
